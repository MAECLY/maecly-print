# IPC and CLI

> **TL;DR** — The Tauri webview talks to the Rust core via typed `invoke()` commands. The same Rust binary doubles as a headless CLI when launched with `--cli` (or any subcommand). Both surfaces share the same handlers in `src/ipc/`, so anything you can do in the dialog you can do from a script. JSON output mode (`--json`) makes the CLI scripting-friendly. Exit codes are documented.

## 1. Two surfaces, one core

```
+-------------+    invoke()    +------------------+   handlers   +---------------+
| Webview UI  | -------------> | Tauri command    | -----------> | Rust modules  |
| (React)     |                | bridge           |              | (queue,       |
|             |                | (src/ipc/)       |              |  engine, etc.)|
+-------------+                +------------------+              +---------------+
                                       ^                                ^
                                       |                                |
                                  +----+-----+                          |
                                  | clap CLI |                          |
                                  | (src/cli/)|-------------------------+
                                  +----------+
```

The Rust modules expose a service trait. Both the IPC bridge and the CLI implement thin adapters that translate input (JSON args / argv) into service-trait calls and translate output (Result types / domain values) into JSON for the webview or stdout for the CLI.

## 2. Tauri IPC commands

All commands live under namespace `app:` (auto-derived) and are declared with `#[tauri::command]`. TypeScript bindings are generated by `tauri-specta` into `src/ipc/bindings.ts`.

### 2.1 Reference table

| Command                   | TS signature                                                   | Rust handler                                            | Notes                              |
| ------------------------- | -------------------------------------------------------------- | ------------------------------------------------------- | ---------------------------------- |
| `list_printers`           | `() => Promise<Printer[]>`                                     | `ipc::printers::list_printers`                          | Rich `Printer` (extends `PrinterInfo` with capabilities) — see [printer-enumeration.md](./printer-enumeration.md) |
| `default_printer`         | `() => Promise<string \| null>`                                | `ipc::printers::default_printer`                        | OS-default id                      |
| `discover_printers`       | `() => Promise<DiscoveredPrinter[]>`                           | `ipc::printers::discover_printers`                      | mDNS/Bonjour on macOS; empty on Windows (deferred) |
| `list_profiles`           | `() => Promise<Profile[]>`                                     | `ipc::profiles::list_profiles`                          | Sorted by `name`                   |
| `get_profile`             | `(id: string) => Promise<Profile>`                             | `ipc::profiles::get_profile`                            |                                    |
| `save_profile`            | `(p: Profile) => Promise<Profile>`                             | `ipc::profiles::save_profile`                           | Returns the saved profile (with id) |
| `delete_profile`          | `(id: string) => Promise<void>`                                | `ipc::profiles::delete_profile`                         | Cannot delete default profile      |
| `set_default_profile`     | `(id: string) => Promise<void>`                                | `ipc::profiles::set_default_profile`                    |                                    |
| `print_files`             | `(req: PrintRequest) => Promise<JobBatch>`                     | `ipc::jobs::print_files`                                | Returns batch ID + per-file IDs    |
| `cancel_job`              | `(id: string) => Promise<void>`                                | `ipc::jobs::cancel_job`                                 |                                    |
| `cancel_all`              | `() => Promise<number>`                                        | `ipc::jobs::cancel_all`                                 | Returns count cancelled            |
| `queue_status`            | `() => Promise<QueueSnapshot>`                                 | `ipc::jobs::queue_status`                               | Snapshot, not a stream             |
| `subscribe_queue`         | event channel `queue-updated`                                  | emitted by dispatcher                                    | Use `listen('queue-updated', ...)` |
| `check_for_updates`       | `() => Promise<UpdateInfo \| null>`                            | `ipc::update::check`                                    | `null` = up to date                |
| `install_update`          | `() => Promise<void>`                                          | `ipc::update::install`                                  | Triggers download + relaunch       |
| `get_settings`            | `() => Promise<Config>`                                        | `ipc::settings::get`                                    |                                    |
| `update_settings`         | `(patch: Partial<Config>) => Promise<Config>`                  | `ipc::settings::update`                                 | Deep-merge patch                   |
| `open_logs_folder`        | `() => Promise<void>`                                          | `ipc::diag::open_logs`                                  | Reveals in Explorer/Finder         |
| `report_issue`            | `(text: string) => Promise<void>`                              | `ipc::diag::report`                                     | Opens GitHub Issues prefilled URL  |

### 2.2 Type definitions

```ts
// src/ipc/bindings.ts
export type PrinterInfo = {
  name: string;
  port: string;
  driver: string;
  is_default: boolean;
  is_local: boolean;
  status: PrinterStatus;
};

export type PrinterStatus =
  | "ready" | "offline" | "paused" | "out_of_paper"
  | "out_of_toner" | "jammed" | "needs_attention";

export type ColorMode = "color" | "monochrome";
export type Duplex    = "off" | "long-edge" | "short-edge";
export type Scaling   = "fit" | "shrink" | "actual";
export type Quality   = "draft" | "normal" | "high";

export type Profile = {
  id: string;
  name: string;
  printer: "<default>" | string;
  color_mode: ColorMode;
  duplex: Duplex;
  copies: number;
  paper_size: string;
  orientation: "portrait" | "landscape" | "auto";
  scaling: Scaling;
  page_range: string;        // "all" | "1-5,8"
  collate: boolean;
  quality: Quality;
  tray: "auto" | string;
  margins_mm: { top: number; right: number; bottom: number; left: number };
  notes: string;
};

export type PrintRequest = {
  files: string[];
  profile_id: string;
  overrides?: Partial<Omit<Profile, "id" | "name">>;
};

export type JobBatch = {
  batch_id: string;
  job_ids: string[];
};

export type JobState =
  | "queued" | "converting" | "converted" | "printing"
  | "done" | "failed" | "paused" | "cancelled";

export type Job = {
  id: string;
  batch_id: string;
  state: JobState;
  input_path: string;
  input_mime: string;
  input_bytes: number;
  cache_pdf: string | null;
  profile_id: string;
  attempts: number;
  error: { code: string; message: string } | null;
  progress: { phase: string; percent: number } | null;
  submitted_at: string;       // ISO 8601
  started_at: string | null;
  finished_at: string | null;
};

export type QueueSnapshot = {
  schema_version: number;
  jobs: Job[];
};

export type UpdateInfo = {
  version: string;
  notes: string;
  pub_date: string;
  size_bytes: number;
};
```

### 2.3 Rust handler example

```rust
// src/ipc/jobs.rs
use tauri::{State, AppHandle, Manager};
use crate::queue::{QueueHandle, JobBatch, PrintRequest};

#[tauri::command]
pub async fn print_files(
    state: State<'_, QueueHandle>,
    app: AppHandle,
    req: PrintRequest,
) -> Result<JobBatch, IpcError> {
    state
        .submit(req, app.clone())
        .await
        .map_err(IpcError::from)
}

#[tauri::command]
pub async fn queue_status(state: State<'_, QueueHandle>) -> Result<QueueSnapshot, IpcError> {
    Ok(state.snapshot().await)
}
```

### 2.4 Events (push from Rust to UI)

| Event name        | Payload                              | Emitted by                                  |
| ----------------- | ------------------------------------ | ------------------------------------------- |
| `queue-updated`   | `QueueSnapshot`                      | Dispatcher on every state transition        |
| `job-progress`    | `{ id: string, phase: string, percent: number }` | Converter & printer adapters     |
| `update-available`| `UpdateInfo`                         | Updater on successful check                 |
| `update-progress` | `{ downloaded: number, total: number }` | Updater during download                  |
| `printer-changed` | `{ name: string, status: PrinterStatus }` | Printer monitor                       |

The webview subscribes via `import { listen } from "@tauri-apps/api/event"`.

Tauri 2's capability system narrows what the webview can call. Our `capabilities/main.json`:

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "main-capability",
  "description": "Permissions for the MaeclyPrint main window.",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "app:list_printers", "app:default_printer",
    "app:list_profiles", "app:get_profile", "app:save_profile",
    "app:delete_profile", "app:set_default_profile",
    "app:print_files", "app:cancel_job", "app:cancel_all", "app:queue_status",
    "app:check_for_updates", "app:install_update",
    "app:get_settings", "app:update_settings",
    "app:open_logs_folder", "app:report_issue",

  ]

```

Anything not listed here is unreachable from the webview — a defense-in-depth measure.

## 3. CLI

### 3.1 Entry point

The same binary detects CLI mode by inspecting `argv`:

- If the first non-flag argument is a known subcommand (`print`, `profiles`, `queue`, `update`, `printers`), or `--cli` is present → CLI mode.
- If `--invoke=context-menu` is present → context-menu mode (just opens the dialog with the supplied files).
- Otherwise → GUI mode (open the main window).

### 3.2 Command reference

```
maeclyprint print --files <FILES> [--profile <NAME>] [--printer <NAME>]
                  [--color | --mono] [--duplex <off|long-edge|short-edge>]
                  [--copies <N>] [--paper <A4|Letter|...>] [--range <SPEC>]
                  [--scale <fit|shrink|actual>] [--quality <draft|normal|high>]
                  [--no-dialog] [--wait]

maeclyprint profiles list [--json]
maeclyprint profiles show <NAME-OR-ID> [--json]
maeclyprint profiles create --name <NAME> [--from <NAME>]
                            [--printer <NAME>] [--color | --mono] [...other flags]
maeclyprint profiles delete <NAME-OR-ID>
maeclyprint profiles set-default <NAME-OR-ID>

maeclyprint printers list [--json]

maeclyprint queue status [--json] [--watch]
maeclyprint queue cancel <JOB-ID>
maeclyprint queue cancel-all

maeclyprint update check [--json]
maeclyprint update install [--yes]
maeclyprint update channel [stable|beta|nightly]

maeclyprint --version
maeclyprint --help
```

### 3.3 Flag semantics

- `--files` accepts a comma-separated list of paths and/or globs (`"*.pdf"`, `"~/Docs/*.docx"`). Globs are expanded by the CLI itself, not the shell, so they work on Windows.
- `--no-dialog` skips the GUI and prints immediately with the provided settings (useful for scripts).
- `--wait` blocks until all jobs reach a terminal state, then exits with the worst exit code among them.
- `--json` switches structured commands (`list`, `status`, `check`) to JSON output.

### 3.4 Examples

```
# Print every PDF in a folder using the default profile
maeclyprint print --files "C:\Reports\*.pdf"

# Print one DOCX with explicit overrides, wait for completion
maeclyprint print --files report.docx --printer "HP LaserJet" \
    --duplex long-edge --color --copies 2 --no-dialog --wait

# Pipe-friendly listing
maeclyprint printers list --json | jq -r '.[] | select(.is_default) | .name'

# Watch the queue
maeclyprint queue status --watch

# Force an update check, install if available, no prompt
maeclyprint update check --json
maeclyprint update install --yes
```

### 3.5 IPC ↔ CLI mapping

| CLI command                                | IPC command                          |
| ------------------------------------------ | ------------------------------------ |
| `print --files ... --profile ...`          | `print_files`                        |
| `printers list`                            | `list_printers`                      |
| `profiles list` / `show`                   | `list_profiles` / `get_profile`      |
| `profiles create` / edit                   | `save_profile`                       |
| `profiles delete`                          | `delete_profile`                     |
| `profiles set-default`                     | `set_default_profile`                |
| `queue status`                             | `queue_status`                       |
| `queue cancel <id>`                        | `cancel_job`                         |
| `queue cancel-all`                         | `cancel_all`                         |
| `update check`                             | `check_for_updates`                  |
| `update install`                           | `install_update`                     |

The CLI implementation in `src/cli/` is intentionally a thin wrapper that calls the same underlying service traits as the IPC handlers. Both surfaces stay in sync because of this.

### 3.6 JSON output mode

With `--json`:

- `list`-style commands emit a JSON array.
- `status`-style commands emit a JSON object.
- Errors emit `{"error":{"code":"...","message":"..."}}` to stderr and exit with the matching exit code below.

Without `--json` we emit human-friendly tables (using `comfy-table`).

### 3.7 Exit codes

| Code | Meaning                                                              |
| ---- | -------------------------------------------------------------------- |
| 0    | All requested operations succeeded.                                   |
| 1    | Generic error (catchall).                                            |
| 2    | Invalid command-line usage.                                          |
| 3    | Configuration error (unreadable / invalid `config.toml` etc.).        |
| 4    | Profile not found / invalid.                                         |
| 5    | Printer not found / invalid.                                         |
| 6    | One or more files not found / unreadable.                            |
| 7    | One or more files unsupported.                                       |
| 8    | Conversion failed (timeout or converter error).                       |
| 9    | Printing failed (spooler reported error).                             |
| 10   | Update check failed (network/signature).                             |
| 11   | Update install failed.                                               |
| 12   | User cancelled.                                                      |
| 64+  | Reserved for future use; never overlap with `sysexits.h`.            |

For batches, the worst (highest) exit code among jobs is returned.

## 4. Error model

A single `IpcError` enum is serialized identically across both surfaces:

```rust
#[derive(thiserror::Error, Debug, Serialize)]
#[serde(tag = "code", content = "message")]
pub enum IpcError {
    #[error("Profile not found: {0}")]
    ProfileNotFound(String),
    #[error("Printer not found: {0}")]
    PrinterNotFound(String),
    #[error("File not found: {0}")]
    FileNotFound(String),
    #[error("Unsupported format: {0}")]
    Unsupported(String),
    #[error("Conversion failed: {0}")]
    ConversionFailed(String),
    #[error("Print failed: {0}")]
    PrintFailed(String),
    #[error("Update check failed: {0}")]
    UpdateCheckFailed(String),
    #[error("Update install failed: {0}")]
    UpdateInstallFailed(String),
    #[error("Cancelled")]
    Cancelled,
    #[error("Internal error: {0}")]
    Internal(String),
}
```

Webview receives `{"code":"FileNotFound","message":"foo.pdf"}`. CLI prints the `Display` form to stderr unless `--json`, in which case the same JSON is written to stderr.

## 5. Stability

- IPC command names and event names are part of the **public surface** of MaeclyPrint and follow semver. Renaming or removing one is a major version bump.
- CLI subcommand names and flags are public surface. New flags can be added in minor versions; existing flags may be deprecated (with a warning) and removed only in a major version.
- JSON output schemas are public surface and versioned implicitly by app version. A `--cli-protocol-version` flag may be added in 2.x.
