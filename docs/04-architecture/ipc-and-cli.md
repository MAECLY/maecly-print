# IPC and CLI

> **TL;DR** — The Tauri webview talks to the Rust core via typed `invoke()` commands generated by `tauri-specta`. The **same binary also ships a headless CLI** (`src-tauri/src/cli/`, clap): `print`, `printers`, `profiles`, `queue` and `update`, plus `--json` for machine-readable output and `--invoke=context-menu --files-from <PATH>` for the shell extensions. Exit codes are frozen public surface and pinned by tests.

## 1. Two surfaces, one core

```
+-------------+    invoke()    +------------------+   handlers   +---------------+
| Webview UI  | -------------> | Tauri command    | -----------> | Rust modules  |
| (React)     |                | bridge           |              | (queue,       |
|             |                | (src-tauri/      |              |  engine,      |
+-------------+                |  src/ipc/)       |              |  profiles,    |
                               +------------------+              |  settings,    |
                                       ^                          |  update, …)  |
                                       |                          +---------------+
                                  +----+----------+                     ^
                                  | clap CLI      |---------------------+
                                  | (src-tauri/   |
                                  |  src/cli/)    |
                                  +---------------+
```

Both adapters are thin. The CLI is explicitly a **facade**: each subcommand calls the same path-injected core the matching Tauri command calls (`ipc::profiles::*_at`, `ipc::settings::*_at`, `platform::*`, `update::*`, `queue::persist`, `engine::*`), so there is exactly one implementation of every rule. The only logic that lives in `src/cli/` is what only a command line needs — argument vocabulary, name→id lookup, file expansion, output formatting and exit codes.

## 2. Tauri IPC commands

Commands are declared with `#[tauri::command] #[specta::specta]` and registered in one place: `tauri_specta::collect_commands!` in `src-tauri/src/lib.rs`. TypeScript bindings are generated into `src/ipc/bindings.ts` (regenerated on every debug launch and by `cargo test`'s `bindings_are_current`, so the file is never hand-edited).

> **Contract decisions worth calling out** (the shipped surface diverges from earlier drafts of this doc):
>
> - **Settings are replace-sections, not deep-merge.** `set_app_settings` overwrites each of the four wire sections wholesale with what the client sends (keeping `printers` + `schema_version`). There is no `update_settings(patch)` deep-merge command; the client sends a complete `AppSettings`.
> - **`list_profiles` ordering is built-ins-first, then customs by name** — not a flat name sort. The three built-ins always lead in canonical order (`Quick`, `Duplex BW`, `Photo Color`).
> - **`save_profile` is an upsert with id-preservation semantics**, which is what makes a client-side "undo delete" restore the same id.
> - **There is no `duplicate_profile` command.** Cloning is a client-side draft (a new profile with an empty id) that `save_profile` creates.
> - **There is no `install_update` command.** The update surface is a read-only check plus the skip/throttle bookkeeping (`get_update_state` / `set_skipped_update_version`). See [auto-updater.md](./auto-updater.md).

### 2.3 Rust handler example

```rust
// src-tauri/src/ipc/jobs.rs
#[tauri::command]
#[specta::specta]
pub async fn print_files(
    state: State<'_, QueueHandle>,
    req: PrintRequest,
) -> Result<JobBatch, IpcError> {
    // `submit` validates and fans the batch out synchronously (off the IPC
    // thread), returning before any job is enqueued — a bad request never
    // reaches the queue. The dispatcher then drives the jobs and pushes
    // `queue-updated` events.
    let handle = state.inner().clone();
    run_blocking(move || handle.submit(req)).await
}
```

### 2.4 Events (push from Rust to UI)

All five events derive `tauri_specta::Event` and are collected in `src-tauri/src/lib.rs`. Event *names* are the struct identifiers kebab-cased by the derive; the webview subscribes through the generated `events` object (`events.queueUpdated.listen(…)`), never raw `listen()`.

| Event name            | TS type / payload                              | Emitted by | Notes |
| --------------------- | ---------------------------------------------- | ---------- | ----- |
| `queue-updated`       | `QueueUpdated` = `QueueSnapshot`               | Dispatcher, on every persisted mutation (submit / transition / cancel / clear / pause) | Full snapshot; the frontend replaces state wholesale |
| `job-progress-event`  | `JobProgressEvent` = `{ id, phase, percent }`  | Dispatcher's conversion progress callback | Throttled ≥ 100 ms, advisory, **not** persisted |
| `update-available`    | `UpdateAvailable` = `UpdateCheck`              | `lib.rs`'s startup thread, via `update::run_startup_check` | Emitted **only** when the preference is on, the 24 h window elapsed, the release is strictly newer, and it is not the skipped one — receiving it is already the decision to tell the user |
| `selection-forwarded` | `SelectionForwarded` = `Selection`             | The single-instance plugin callback, and the macOS Finder service | A second launch handed this window a file selection. The payload is informational: the same selection is also parked in the pending store, and the window acts on it by calling `take_pending_selections` — one destructive drain, so a selection can never be honoured twice |

| `update-download-progress` | `UpdateDownloadProgress` = `{ downloaded, total }` | `install_update`, per received chunk | Bytes so far and the `Content-Length` when known; advisory |

There is no `printer-changed` event.

### 2.5 Capability declaration

Tauri 2's capability system gates **core and plugin** permissions (window, webview, dialog, …) per window. It does **not** gate the app's own `#[tauri::command]` handlers: commands registered through `collect_commands!` / `invoke_handler` are the application's private IPC surface and are callable from the main window regardless of the capability list. So `capabilities/main.json` carries only the core defaults plus the one plugin permission we actually use:

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "main-capability",
  "description": "Permissions granted to the MaeclyPrint main window.",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "core:window:default",
    "core:webview:default",
    "dialog:default"
  ]
}
```

`dialog:default` grants the native file-picker plugin the Print Job screen uses. (`tauri-plugin-opener` and `tauri-plugin-single-instance` are called from Rust only, so they need no JS capability.) The defense-in-depth boundary for the app's own commands is therefore twofold, and does **not** come from a per-command allowlist:

1. **Closed surface.** Only the commands enumerated in `collect_commands!` exist at all.
2. **No remote code.** The window's CSP loads only the bundled SPA and forbids remote content (see [`security-model.md`](./security-model.md) § 3.3), so there is no attacker-controlled script in the webview to call them.

## 3. CLI

> **Status: shipped.** `src-tauri/src/cli/` implements the whole surface below, `update install` included.

### 3.1 Entry point

`cli::startup(argv)` classifies the command line **before** the Tauri builder runs — a headless run never creates a webview. `cli::classify` inspects argv without parsing it, and the first **non-flag** argument decides:

1. `--invoke=context-menu` (or `--invoke context-menu`) → **context-menu mode**: the app opens with the supplied selection. This outranks everything, so a shell-extension launch can never be reinterpreted as a subcommand.
2. `--cli`, `--help`/`-h`, `--version`/`-V`, or a known subcommand (`print`, `printers`, `profiles`, `queue`, `update`) → **headless mode**, no window.
3. A bare argument naming an existing path → **GUI mode** ("open with" launch). Every such path (absolutized against the launch's working directory, then resolved by `canonical_input`) becomes a `configure` selection (`cli::open_with_selection`), so the app opens on the Print Job screen with the files loaded.
4. Anything else → headless, so clap can answer "unrecognized subcommand" with a non-zero code instead of silently opening a window.
5. No arguments (or only platform noise such as macOS' `-psn_0_12345`) → **GUI mode**.

**Windows: two executables.** `maeclyprint.exe` is a GUI-subsystem program, so a double-click never flashes a console. Its headless path calls `cli::console::attach_parent()` first — `AttachConsole(ATTACH_PARENT_PROCESS)`, then `CONOUT$` for any standard handle that is still empty, while handles the caller redirected (`> out.txt`, a pipe) are kept — so output reaches the terminal. What it cannot change is that `cmd.exe` and PowerShell **do not wait** for a GUI-subsystem program: the prompt returns at once and `%ERRORLEVEL%` / `$LASTEXITCODE` never see the exit code.

Scripts therefore use **`maeclyprint-cli.exe`**, installed next to it (`src-tauri/src/bin/maeclyprint-cli.rs`): a console-subsystem build of the same CLI, run in-process, whose exit status is the §3.7 code. When its command line asks for the GUI (no subcommand, a context-menu invocation, an "open with" path) it starts `maeclyprint.exe` detached with the same arguments and exits 0, so a terminal is never held open by a window. Calling `maeclyprint.exe` itself from a script needs `start /wait maeclyprint.exe …` (cmd) or `Start-Process -Wait -PassThru` (PowerShell) to get the code. Both executables flush stdout/stderr before exiting (`cli::exit_process`). On macOS and Linux both are plain console programs.

**Second launches.** `tauri-plugin-single-instance` intercepts a second process and forwards its argv to the running instance, which re-interprets it (`cli::single_instance`) and emits `selection-forwarded` (NFR-014). Both a context-menu argv and an "open with" argv (absolute paths only — the running instance has a different working directory) resolve to a selection. The pending store is created **before** the Tauri builder and shared with the plugin callback, so a selection forwarded while the first instance is still cold-starting (before `setup`) is kept and drained with the launch's own selection, which stays first. A headless subcommand exits before that ever matters.

**Who deletes the handoff file.** The same argv is therefore interpreted *twice* — once by the process that was launched, once by the instance that actually owns the window — so reading a handoff file never deletes it (`cli::handoff::read_file`). The delete happens in whichever process ends up **parking** the selection: `PendingSelections::park_launch` when this process boots the window, or the single-instance callback when the selection was forwarded. It is always best effort, and `cli::handoff::sweep` collects anything left behind. The macOS service is the one exception: it writes and reads the file inside one process, so it can `consume` it outright. None of this weakens the validation gate — schema version, freshness window, directory containment and the size/path caps apply to every read.

### 3.3 Flag semantics

- `--files` takes a comma-separated list. Each entry may be a plain path, a **directory** (walked recursively with the same `engine::expand_folder` the GUI uses, filtered by `max_file_size_mb`), or a **wildcard in the last path component** (`C:\Reports\*.pdf`). Patterns are expanded by MaeclyPrint, not the shell, so they behave identically in `cmd.exe` and in bash. A pattern or folder matching nothing is an error naming the entry.
- Relative paths are resolved against the working directory **only here**; every other surface refuses them (`util::paths::canonical_input`, NFR-025).
- `--files-from <PATH>` reads a JSON handoff file instead of argv — how the shell extensions pass a large selection past Windows' 32,767-character argv cap. A handoff file is untrusted input: it must resolve **inside** the per-user handoff directory (`<data dir>/handoff`) and be fresh, or it is refused.
- `--duplex`, `--paper`, `--scale`, `--orientation`, `--quality` are case-insensitive. `--scale actual` is the engine's `none` — the one deliberate rename.
- `--printer` accepts the spooler **queue id** (`HP_LaserJet_Pro_M404`) or the **display name** `printers list` shows (`HP LaserJet Pro M404`, CUPS `printer-info`), the id ignoring case as CUPS does. Either way the job is spooled to the matched queue id, never to the text typed. A display name shared by several queues is refused with exit code `Printer` and the candidate ids; pass the id instead. The queue applies the same rule to a profile's printer (an unmatched or ambiguous name pauses the job as `PrinterMissing`).
- With no `--printer`, the target is the file-type route, then the org-policy default (`policy.json`), then the app default, then the OS default — the same chain the GUI queue uses.
- `--color` and `--mono` are mutually exclusive; omitting both leaves the profile's value. The same holds for `--collate` / `--no-collate`.
- `--no-dialog` and `--wait` are accepted for compatibility and are **no-ops**: a headless `print` never opens a window and always runs each file to completion before exiting.
- `--json` switches every command to JSON on stdout; errors become JSON on stderr.

**What `print` does *not* do.** A headless print is a foreground operation, so it deliberately differs from the GUI queue in three ways: it never touches `queue.json` (so it cannot race a running app for it), it converts into a private temp directory deleted on exit (so neither process can delete the other's work), and it has **no retry/backoff** — a script wants an exit code, not a job that quietly retries.

**What `queue` does *not* do.** `queue status|cancel|cancel-all` operate on the persisted `queue.json` through `queue::persist`, guarded by the same `can_transition` rules the dispatcher uses. They do **not** reach into a running app: a live instance owns its queue in memory and rewrites the file on every transition, so a cancel written to the file while the app is open would be overwritten — and reported as a success while the job kept printing. The app therefore holds an exclusive OS lock on `<data_dir>/instance.lock` for its whole lifetime (`cli::instance`; released by the OS however the process ends), and `queue cancel` / `cancel-all` check it before reading and again before writing: while the app runs they **fail** with `InvalidState` (exit code 1) and change nothing, telling the user to cancel from the Queue screen. `queue status` stays available (it only reads what the app persists). The offline path is what makes `queue status` useful in a script and `queue cancel` useful on a queue left behind by a closed app.

### 3.5 IPC ↔ CLI mapping

Both surfaces call the same core; the table names the shared implementation rather than implying the CLI invokes the Tauri command.

| CLI command                 | Shared core                                              | Sibling IPC command |
| --------------------------- | -------------------------------------------------------- | ------------------- |
| `print`                     | `engine::convert` → `engine::print::spool` (no queue)     | `print_files` (queued) |
| `printers list`             | `platform::list_printers`                                 | `list_printers` |
| `profiles list` / `show`    | `ipc::profiles::list_profiles_at` / `get_profile_at`      | `list_profiles` / `get_profile` |
| `profiles create`           | `ipc::profiles::save_profile_at`                          | `save_profile` |
| `profiles delete`           | `ipc::profiles::delete_profile_at`                        | `delete_profile` |
| `profiles set-default`      | `ipc::profiles::set_default_profile_at`                   | `set_default_profile` |
| `queue status`              | `queue::persist` (reads `queue.json`)                     | `queue_status` (live) |
| `queue cancel` / `cancel-all` | `queue::persist` + `can_transition`                     | `cancel_job` / `cancel_all` |
| `update check`              | `update::fetch_latest` + `update::evaluate`               | `check_for_updates` |
| `update channel`            | `settings::Config` `[updater].channel`                    | `get_app_settings` / `set_app_settings` |
| `update install`            | `update::install::{find_update, install}` through a windowless Tauri app (`headless_updater_app`) | `install_update` |

#### `update install`

`update install` runs the same core as `install_update`. Without `--yes` it asks on an interactive terminal (`[y/N]`; a major update is named as such, FR-087), exits **2** when there is no terminal to ask, and exits **12** when the answer is not yes. A rejected signature or any other install failure exits **11**. `MAECLYPRINT_UPDATE_ENDPOINT` replaces the manifest URL for local end-to-end tests. With `--json`, stdout is the `UpdateInstallResult` (`{"installed": "0.2.0", "restart_required": true}`, or `"installed": null` when up to date).

### 3.6 JSON output mode

With `--json`, **stdout carries nothing but the JSON document** (so `| jq` works), and errors go to stderr as `{"error":{"code":…,"message":…}}` — the same `{code, message}` envelope the webview receives, so a script and the UI never see two different names for the same failure.

Without `--json` the CLI prints a plain left-aligned text table (`cli::output::table`). Earlier drafts named `comfy-table`; it is **not** a dependency, and one table helper did not justify one.

### 3.7 Exit codes

Frozen public surface, defined by `ExitCode` in `src-tauri/src/cli/exit.rs` and pinned value-by-value by `cli_contract.rs`, so changing one fails the build rather than silently breaking a caller.

| Code | Name                  | Meaning |
| ---- | --------------------- | ------- |
| 0    | `Success`             | All requested operations succeeded. |
| 1    | `Generic`             | Generic error (catchall). Also where `JobNotFound` / `InvalidState` / `Internal` land — they have no dedicated code. |
| 2    | `Usage`               | Invalid command-line usage. Every clap failure except `--help`/`--version`, which exit 0. |
| 3    | `Config`              | Configuration error — unreadable/invalid `config.toml`, **or a missing external dependency** (`lp`, SumatraPDF): that is an environment fault, not a usage one. |
| 4    | `Profile`             | Profile not found / invalid. |
| 5    | `Printer`             | Printer not found / invalid — including **a setting the driver refuses** (`UnsupportedSetting`: the flag was legal, the device is the problem) and "no printer configured at all". |
| 6    | `FileNotFound`        | One or more files not found / unreadable. |
| 7    | `UnsupportedFile`     | One or more files unsupported. |
| 8    | `ConversionFailed`    | Conversion failed (timeout or converter error). |
| 9    | `PrintFailed`         | Printing failed — the spooler reported an error, **or the print hop timed out** (it took the job and never finished). |
| 10   | `UpdateCheckFailed`   | Update check failed (network, rate limit, misconfigured repository). |
| 11   | `UpdateInstallFailed` | Update install failed: download, a rejected signature (`UpdateSignatureInvalid`), the installer, or a copy of the app that cannot update itself. |
| 12   | `Cancelled`           | User cancelled. |

For batches, `ExitCode::worst` returns the highest code among the files, so one failure in fifty is never reported as success.

## 4. Error model

A single `IpcError` enum is serialized identically to the webview and to a `--json` CLI run (`src-tauri/src/util/error.rs`):

```rust
#[derive(thiserror::Error, Debug, Serialize)]
#[serde(tag = "code", content = "message")]
pub enum IpcError {
    #[error("File not found: {0}")]            FileNotFound(String),
    #[error("Invalid request: {0}")]           InvalidRequest(String),
    #[error("Unsupported file format: {0}")]   UnsupportedFormat(String),
    #[error("Conversion failed: {0}")]         ConversionFailed(String),
    #[error("Printing failed: {0}")]           PrintFailed(String),
    #[error("Unsupported setting: {0}")]       UnsupportedSetting(String),
    #[error("Missing dependency: {0}")]        DependencyMissing(String),
    #[error("Job not found: {0}")]             JobNotFound(String),
    #[error("Invalid state: {0}")]             InvalidState(String),
    #[error("Profile not found: {0}")]         ProfileNotFound(String),
    #[error("Update check failed: {0}")]       UpdateCheckFailed(String),
    #[error("Update install failed: {0}")]     UpdateInstallFailed(String),
    #[error("Update signature invalid: {0}")]  UpdateSignatureInvalid(String),
    #[error("Internal error: {0}")]            Internal(String),
}
```

The webview receives `{"code":"FileNotFound","message":"foo.pdf"}`. The CLI prints the `Display` form to stderr as `error: …`, or — with `--json` — the same payload wrapped as `{"error":{…}}`. `exit::exit_code_for` is the default `IpcError` → exit-code mapping; a call site that knows better overrides it with `CliError::new`.

## 5. Stability

- IPC command names and event names are part of the **public surface** and follow semver. Renaming or removing one is a major version bump.
- CLI subcommand names, flag names and **exit-code numbers** are public surface. New flags can be added in minor versions; existing flags may be deprecated (with a warning) and removed only in a major version.
- JSON output schemas are public surface and versioned implicitly by app version. A `--cli-protocol-version` flag may be added in 2.x.
